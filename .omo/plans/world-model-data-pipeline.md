# world-model-data-pipeline - Work Plan

## TL;DR (For humans)
**What you'll get:** A PyTorch-ready input pipeline that safely reads completed visual-action rollouts while more rollouts are being collected. It will provide reproducible temporal windows, curriculum schedules, and named fixed-versus-temporal-adaptive experiment configurations.

**Why this approach:** A training run captures a fixed list of already-valid episodes, so partially written collector output cannot enter halfway through an experiment. The curriculum is an explicit function of saved training progress and configuration, making resumed runs and ablations comparable.

**What it will NOT do:** It will not train a JEPA/world model, generate scene graphs or event labels, add simulator instrumentation, or alter active rollout artifacts. It will not claim symbolic or joint temporal-symbolic controller results before the required labels and models exist.

**Effort:** Large
**Risk:** Medium - the collector's artifact contract must be reproduced exactly enough to reject live partial output without excluding valid completed episodes.
**Decisions I made for you:** Use a standalone `world_model/data` package with PyTorch `Dataset`/`DataLoader` and a dedicated world-model dependency file; snapshot only validated episode paths in memory; expose image transforms and temporal schedules as explicit configuration; preserve the existing level-level train/dev/test partition and add explicit test collection rather than re-splitting frames or shots.

Your next move: start the reviewed plan with `$start-work world-model-data-pipeline`. Full execution detail follows below.

## Scope
### Must have
- A typed `world_model/data` package backed by one public canonical artifact validator shared with collection planning, producing immutable per-run catalogs from `train`, `dev`, or `test` directories.
- A forward-compatible capture-contract descriptor that preserves an episode's schema/provenance and declared supervision capabilities without parsing unavailable symbolic/physics payloads in this workstream.
- Lazy RGB image decoding and action-conditioned temporal-window samples for accepted shots, plus deterministic PyTorch sampling/collation.
- Declarative, checkpoint-resumable curriculum policies over novelty level, scenario/type, shot progress, stride, and horizon.
- Named fixed-stride and temporal-only-adaptive ablation configurations with emitted matched-budget accounting.
- A dataset inspection command that reports accepted/rejected episodes, window availability, split composition, and curriculum composition without modifying the raw root.
- Test-collection support across the planner and launcher while preserving the current train/dev default behavior.
- Unit and integration coverage using synthetic rollout fixtures, plus a read-only smoke inspection of the active rollout root.

### Must NOT have (guardrails, anti-slop, scope boundaries)
- No world-model/JEPA encoder, predictor, trainer, controller policy, distributed training, or Lightning integration.
- No scene-graph, contact/support, velocity/kinetic-energy, or macro-event payload parsing, tensorization, curriculum use, inferred labels, or engine changes. This plan may carry declared capability names and validated sidecar paths only; the physics-instrumentation plan owns payload readers once a real schema exists.
- No re-partitioning of episodes, frames, or shots; no test examples may be inferred from train/dev data.
- No mutation, repair, deletion, copying, or lock ownership of the active raw rollout directory.
- No hidden random state, epoch-dependent filesystem rescan, cross-rank/distributed-training surface, or ablation whose effective horizon/sample/compute budget is unreported.

- Required invariants: every catalog entry resolves beneath its declared split; catalog results are stable after construction; a catalog records rejection reasons for malformed or concurrent-write artifacts; a sample's frames are contiguous and within one accepted shot; source-level split disjointness is checked when a collection-plan manifest is supplied (and reported unavailable otherwise); declared capture-contract capabilities and sidecar paths are immutable provenance only; and each ablation report states its seed, draw count, stride/horizon distributions, effective prediction steps, and temporal-controller cost.
