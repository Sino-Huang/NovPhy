CIRCULAR IMPORT RESOLUTION
The catalog module imports from scripts.rollout_artifacts which itself imports from world_model.data.
This creates a circular dependency at module load time. Resolution: catalog.py uses local (function-level)
imports for validate_rollout_episode, EpisodeAccepted, and EpisodeValidationContract, deferring them
until first use rather than at module initialization.

CONTRACT OBSERVABLES
- EpisodeCatalog.build() enumerates only direct non-symlink subdirectories of root/split.
- Symlinks at the split level are silently excluded (counted as rejection by validator or skipped at enumeration).
- Files (non-directories) at the split level are silently skipped.
- When collection_plan is supplied, source_level_key is the exact plan relative_path; provenance_available=True.
- When collection_plan is absent, source_level_key=None for all episodes; provenance_available=False.
- physics_capture_v1 descriptor in manifest results in rejection_codes=('unsupported_capture_contract',).
- Unknown contract name results in rejection_codes=('unknown_capture_contract',).
- Required capability not declared in capture_contract raises ValueError immediately (fail-closed).
- check_source_key_disjointness raises ValueError when two plan-backed catalogs share a source key.
- catalog.episodes is an immutable tuple; assignment raises AttributeError.
- refresh() returns a new EpisodeCatalog instance; original episodes tuple is unchanged.
- No JSONL payload is parsed; no sidecar files are opened or compared.
- No file is written inside the raw rollout root.
