# #73: action headroom, timing and controller diagnostic

This is an exploratory read-only analysis of accepted training/calibration
evidence. No fitting, new rollout collection, fresh/final access, optimizer
change or historical-result rewrite is authorized.

## Questions and inventories frozen before new diagnostic tables

- Use all 200 #72 calibration states and all 12 recorded candidates per state.
  Bind the #72 source plan/result, source-repair receipt and trained #71 models.
- Define best-of-grid as the minimum *observed* accepted settled engine count
  cost, with original ordinal breaking ties. It is not a deployable policy, a
  global action optimum, or a multi-shot oracle. Keep failed candidates/states.
- Compare the three model selections, the #72 frozen prior and uniform-random
  expectation to this bound: absolute count cost, normalized regret, best-set
  tie size, top-k, missed lower-cost outcomes and missed pig/contact/progress
  opportunities. Report count, pig-removal, level-clear, contact, displacement
  and support-change outcomes separately. No contact/movement-to-collapse or
  one-shot-failure-to-unsolvability inference.
- Metadata can establish remaining counts and recorded coverage/progress.
  Authoritative block destruction and health/damage availability are checked in
  the bounded raw-trace audit, not invented from remaining counts or pixels.
- Audit all 12 candidate traces at eight calibration ordinals uniformly spread
  from 1 to 200 (96 captures). Inspect capture/action/launch/first collision/
  settling times, step-225 versus settled counts, frame spacing and first-window
  activity. Also inspect every shot of 12 uniformly selected controller-training
  lineages (indices 5, 255, ..., 2755); compare their first and later windows.
- On those eight calibration states, compare fixed continuous h1/h5/h15 and
  adaptive using the SAME corrected hybrid checkpoint and identical 12 actions
  and B=1 carrier. This does not create the missing pure-continuous baseline.
- On the 12 training-role lineages, compare observed-context versus recursive
  transitions, their availability masks and controller DP labels against
  deployed choices. Keep carrier MSE, DP utility and task cost distinct.
- Gallery: bounded, deterministic examples of missed pig-removal, missed count
  reduction, contact-only progress and no recorded useful outcomes, plus high-arc
  cases. Outcome-selected review examples are explicitly exploratory and do not
  change membership or result denominators. Reuse existing normal-playback WebMs
  with source IDs and event timestamps; disclose missing or irregular frames.

## Branch decision and limitations

Report evidence for source/time alignment, model-ranking/controller loss and
limited grid headroom separately; mixed or insufficient evidence is allowed.
Do not pick an optimizer from negative evidence alone. Any proposed follow-up
is ONE bounded intervention with cost estimates, matched-baseline requirements
and a prospective stop rule, owned by #74/#75 rather than implemented here.

In particular, a pre-launch observation is an agent-available state; an observed
post-drag/post-launch frame from a candidate replay is not automatically a valid
counterfactual input for scoring other actions. Any timing correction must not
introduce this future/action-dependent information into deployment.

Existing #71/#72 gates and interpretations stay unchanged. All newly computed
diagnostics are development evidence, not proof of hybrid superiority or an
authorization for #64. The independent pure-continuous dynamics model remains
required under #74, with shared semantic perception explicitly disclosed.

## Runtime / evidence requirements

Stream one state or raw capture at a time; do not load the image corpus. Use
source metadata and existing artifacts without new hashes or integrity scans.
Freeze a machine-readable plan with exact code/source references before --run.
Provide resumable stage/state progress and ETA, a no-write dry run, a bounded
real-data smoke, regression tests, and exact publication validation. Timing,
controller and gallery tasks must also show progress. Long jobs are left to the
operator after a measured smoke estimate. Preserve original artifacts and all
technical repair records; distinguish local source snapshots from archived code.
