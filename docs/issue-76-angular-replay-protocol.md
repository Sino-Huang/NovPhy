# Prospective angular action-design pilot

The completed original-grid diagnostic remains negative: zero native clears,
four comparable lineages, poor fixed-model ranking and a stronger simple prior.
This separate training-only pilot tests whether better angular coverage provides
useful action headroom. It does not rescue those results or change #76's gates.

Use the identical first assigned training lineages 001/071/141/211/281, original
XML, scenario identity, generation seed and engine seed. Preserve all five,
including 071's previously failed comparability. Give all 65 assignments new
`issue-76-angular-replay` rollout IDs. Within each family first repeat the
original (-80,10) reference, then twelve angles 5+7k degrees, k=0..11, commanded
radius 80 pixels with integer-rounded coordinates. Release 600 ms; tap 0 ms.
The reference is outside the twelve-action ranking pool. No outcome, geometry
or model preference selects angles or membership.

One worker, one shot per assignment, unchanged native player and actuator
readiness. Capture at native step 0.0004 seconds, RGB stride 50, maximum 30,000
steps/12 physical seconds and 601 frames. Limits: 14,400 collection wall seconds,
420 per attempt, 180 shot wait, 4 GiB worker-tree RSS and 32 GiB total pilot
artifacts including player/runtime copies. Zero technical retries, replacement
levels or extra seeds. The prior same-size collection measured 6,882.05 seconds
and 12.26 GB; this is a planning reference, not guaranteed new-run cost.

The first family's reference and first angle are the rendered smoke, within
1,200 seconds and included in the 65 assignments. Continuation is based only
on capture integrity, source bindings, resource compliance and the unchanged
prospective comparability tolerances in `issue-76-replay-execution.md`, including
all birds. Preserve failed comparisons and make their whole lineage inadmissible
for paired ranking. Do not relax tolerances after capture. Keep genuine
pre-decision RGB distinct from the later first physical sample.

Allow 1,800 CPU wall seconds for validation/outcome reporting, zero CUDA scoring
and zero optimizer updates. Preserve 1e9 penalties for native failures, censoring
and invalid outcomes. Count actual native level-clear events separately from
stable endpoints and pig/block counts. Retain all assigned outcomes and publish
the full candidate table; all failed/tied states are not useful ranking evidence.

For this pilot alone, call the action design viable for further protocol design
only if at least four lineages are comparable and at least three comparable
lineages have a verified native-clear grid action. This is a feasibility screen,
not a statistical advantage test: repeated actions are not independent units,
and these five lineages are already-opened training development data. A pass
authorizes neither training nor fresh evaluation; a separate source-bound plan
would be needed. A failure is retained as insufficient action-design readiness,
not followed by an automatic angle or optimizer sweep.

Inventory preparation does not authorize capture. Before rendering, implement
and test the source-bound execution driver, archive its code and plan, then
validate the bounded smoke. No #64/#65 authorization follows from this pilot.
