Key design invariants confirmed
1. PNG decoding is lazy: __init__ never calls Image.open; only __getitem__ does.
2. Index is deterministic: built from catalog.episodes (immutable tuple) in episode -> shot -> start_frame order.
3. Frame paths are catalog-root-relative: catalog.py _build_episode_record_from_validated rebases paths; dataset uses root / frame.relative_path directly.
4. Action is strict [5]: torch.tensor([float(v) for v in shot.action.values], dtype=torch.float32).
5. FrameReadError is typed IOError: catches OSError/IOError from Image.open and wraps; callers can distinguish from ValueError.
6. No sidecar access: dataset.py has no JSONL/JSON reads; only PIL Image.open for PNG frames.
7. Snapshot stability: EpisodeCatalog is immutable after build(); adding files does not affect an existing dataset index.

Root cause confirmed:
  catalog.py _build_episode_record_from_validated rebases FrameRecord.relative_path
  to be catalog-root-relative (e.g. train/episode_001/shot_001/frames/frame_000000.png).
  A prior fix had added episode.relative_path as a prefix again, producing:
    root / "train/episode_001" / "train/episode_001/shot_001/frames/frame_000000.png"
  which resolves to a non-existent doubled path.

  (b) NoEligibleTemporalWindowError renamed as primary; NoEligibleWindowError
      kept as a backwards-compatible alias.
  (c) FrameReadError catches only (OSError, UnidentifiedImageError); removed
      redundant IOError alias and overly broad SyntaxError.
