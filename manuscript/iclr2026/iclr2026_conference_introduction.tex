\section{Introduction}
\label{sec:introduction}

\begin{revblock}
World models let embodied agents evaluate candidate actions by their imagined outcomes \citep{hansen2022tdmpc,assran2025vjepa2,zhou2025dinowm}.\footnote{\rev{Text added or changed in this revision is shown in blue.}} Many physical interactions are action-sparse with persistent effects: after a single throw, push or release, objects keep moving, collide and trigger chain reactions without further action. Imagining such an outcome requires two choices: how far each prediction reaches and at what level of description it advances the state. Physical simulators adapt both: integrators control their step size \citep{hairer1993solving}, rigid-body engines reduce it near collision \citep{mirtich2000timewarp}, and less important scene components are simulated at lower detail \citep{carlson1997simulation}. A world model with one temporal stride and one predictive representation fixes both choices before deployment.
\end{revblock}

\begin{revblock}
Such environments are action-sparse Markov decision processes (MDPs), with null actions between rare decisions. Many implementations predict at a fixed temporal stride and with a fixed predictive representation. We expose horizon and description mode as query inputs while retaining the underlying action-sparse MDP. Horizon determines how much passive dynamics a query skips. Description level determines which object relations or scene predicates are predicted and fed back. Existing methods choose the horizon per step \citep{neitz2018adaptive,chatterjee2025improving}, tie temporal scales to abstraction levels \citep{lecun2022path}, or vary the description alone \citep{wang2023dynamic,liang2025visualpredicator}. These designs do not expose both axes as independent per-query inputs on one predictor. Our interface does (Section~\ref{sec:rel}). Because every request returns the same carrier, a rollout can switch either axis without translating between separately trained latent spaces.

Each world-model query carries a request $r=(\Delta,\alpha)$: advance $\Delta\in\{1,5,15\}$ carrier frames at description level $\alpha\in\{\textsf{cont},\textsf{micro},\textsf{macro}\}$ (Figure~\ref{fig:interface}). One shared predictor serves all nine requests, and a policy distilled from dynamic-programming labels that trade prediction error against compute picks a request per query. This design separates the interface claim that one model supports multiple granularities from the selection claim that per-query choice improves launch ranking. We test the second against fixed requests, a no-model prior and direct success prediction.

On NovPhy \citep{pinto2024novphy}, one slingshot launch starts a cascade that decides success. The agent ranks a level's 16 grid launches by the cost of each imagined endpoint. Ordering AUC measures whether engine successes receive lower predicted costs than failures, with 0.5 denoting chance. Levels were split before recording into 480 predictor-fit, 120 policy-fit and 400 held-out, within-distribution evaluation levels. The no-model prior scores each launch by its predictor-fit success rate. Separate pixel studies on CLEVRER \citep{yi2020clevrer} and Physion-Dominoes \citep{bear2021physion} test rollout error under different carriers and training recipes.
\begin{itemize}
  \item \textbf{C1, one predictor for nine requests.} At matched per-request updates (9,000 total for the shared model and 1,000 for each single-request specialist), sharing improves nine-request mean AUC by $+0.0848$ [$0.0742$, $0.0952$]. With 9,000 updates per model, specialists instead rank above the shared predictor on five of the six $\Delta=5/15$ requests, while sharing retains its advantage at $\Delta=1$ (Section~\ref{sec:res:sharing}).
  \item \textbf{C2, low rollout error does not imply better ranking.} Rollout-error ordering depends on the training recipe and benchmark. On the NovPhy grid, $\Delta=1$ has the lowest error, but the highest-AUC fixed request on the same predictor uses $\Delta=15$. The pixel studies reverse this error ordering. Error alone therefore does not identify the highest-AUC request (Section~\ref{sec:res:rollout}).
  \item \textbf{C3, the best fixed coarse request outperforms the tested selectors.} At 9,000 updates per predictor, fixed ($\Delta=15$, continuous) requests on the continuous predictor reach 0.783 AUC, compared with 0.706 for $J$. A full-budget single-request specialist reaches 0.885. On one checkpoint, joint selection exceeds continuous-only selection by $+0.0201$ [$0.0154$, $0.0248$] AUC at higher compute (Section~\ref{sec:res:ranking}).
  \item \textbf{C4, direct success prediction is the stronger launch-ranking baseline.} Neither the pre-declared $U=F(15,\textsf{macro})$ nor $J$ establishes an advantage over the no-model prior. A direct success classifier, matched to the shared predictor in total updates, reaches 0.976 AUC against $U$'s 0.744. A separately trained readout classifier with $U$'s predicted endpoint as an extra input changes AUC by $-0.0044$ [$-0.0081$, $-0.0014$] relative to its no-rollout control (Sections~\ref{sec:res:ranking},~\ref{sec:res:live}).
\end{itemize}
\end{revblock}
